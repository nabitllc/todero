### 4. Self-chain (selfChainOnStatus)
Every PATCH that changes status fires `/api/run-agent` for the lane that picks up the new status. Converts the pipeline from poll-driven (30-min watchdog) to event-driven (instant hand-offs). Also reverted multiple times, also now protected by pre-commit hook.

### 5. Worktrees restricted to code agents only
Only `builder` and `ops` (Ingo) get worktrees now. Tester, designer, PO, auditor, deployer, SMEs no longer create branches or worktrees. They only PATCH issue fields via API. This stopped the creation of 200+ zombie `feat/designer-notask-*` branches per day.

### 6. Discord notification routing fixed
Channel IDs in code were mismatched with actual Discord channel names (channels had been renamed on Discord's side). Full audit + reroute:
- Rejections → `#2-rejected` (was `#3-signoff`)
- Escalations → `#escalations` (new channel)
- Approved → `#3-ready-for-deploy` (was `#3-signoff`)
- Closed → `#4-done` (was `#3-signoff`)
- Created → `#0-created` (hook added in POST /api/issues)

Removed 6 dead channel IDs from the notify registry. Fixed `postDiscord()` to log non-2xx responses to stderr (was silently swallowing HTTP errors).

### 7. pr-window.py upgraded
- **Rebase before merge**: each feature branch gets `git rebase main` before merging into the release branch. Prevents stale-branch conflicts.
- **Auto-merge**: squash-merges the PR via GitHub API immediately after creation. The PR is an audit trail, not a review gate (tester+designer already reviewed during code_review).

### 8. Pipeline orchestrator + watchdog consolidation
Went from 5 overlapping watchdogs to 1 unified `pipeline-watchdog.sh` (every 30 min):
- Per-lane health check: ACTIVE/STUCK/IDLE_WITH_WORK/IDLE classification
- Strategic: feature pipeline depth, Telegram alerts on empty queue, Builder+PO escalation
- Worktree GC, stale claim clearing
- Discord summary only when something notable happened

Removed: aggressive-kicker-5min, pipeline-orchestrator, po-builder-check, agent-watchdog-30min, monitor-stale, monitor-stale-smoke.

## Corrections to promote to self-improving

- **"This is too technical for me"** — when Michael says this, switch from explaining options to recommending ONE option and executing. He trusts the engineering judgment; he doesn't want to evaluate trade-offs.
- **Check the BUILD, not the source.** The source file can say anything; what matters is what's compiled into `.next/server/`. Always verify changes in the built bundle after `next build`.
- **Kill all next-server processes before building.** Concurrent builds race and corrupt `.next/`. There should never be >1 next-server process.
- **grep for minified names fails.** After Next.js minification, function names get renamed. Grep for string literals (like channel IDs or status names) that survive minification, not function names.

# 2026-04-11 — Preview-to-Prod Consolidation + Rejection Loop Fix

## Session Context
Michael hit a ChunkLoadError on /team from the production deployment after I ran a `next dev` preview against the same `.next` directory as prod. Then a cascade of related issues surfaced: board columns empty, Telegram bot timing out on screenshots, 7 blocked issues piling up from the rejection loop, and Sidebar hydration mismatches.

Ended with: single-port topology, rejection-aware spawn prompts, inbox table live in Supabase, and all 7 blocked issues unstuck.

## Critical Bugs Fixed

### Bug 1 — `next dev` wiped prod `.next/` chunks
Running Claude Preview `next dev` against the same `.next` as prod deleted BUILD_ID and vendor chunks mid-request. Every browser got ChunkLoadError 404s on `/team`.

**Temp fix:** `distDir: process.env.NODE_ENV === 'development' ? '.next-dev' : '.next'` in `next.config.js` to isolate dev output.

**Permanent fix (later in session):** Option C — drop Claude Preview entirely. `work.nabit.todero` now runs `next dev -p 3000` directly. One process, one port, no preview server, no dual-dir split. Chrome MCP replaces preview_* tools.

### Bug 2 — Board Ongoing/Achieved columns empty at sprint rollover
`components/tabs/BoardTab.tsx:441` filtered everything against today's sprint_date. After the 2026-04-10 → 2026-04-11 rollover, 29 in-flight items (in_progress/code_review/approved/completed/released) were on the closed sprint → invisible.

**Fix:** Added `IN_FLIGHT_STATUSES = ['in_progress','code_review','product_review','approved','released','completed']`. These bypass the sprint filter entirely — once committed work, always visible. Queue column stays sprint-scoped (that's the intent). Permanent fix that doesn't require daily sprint backfills.

### Bug 3 — Hydration mismatch on every page load (Sidebar + AgentsTab)
Two root causes:
1. `app/page.tsx:100` — `useState<Tab>(() => …)` read URL/localStorage on client but returned 'overview' on server. Fixed: always start with 'overview', restore URL/localStorage in a post-mount `useEffect`. Michael later reverted this (intentional), presumably because the URL-restore path is acceptable and the hydration mismatch is cosmetic.
2. `components/tabs/AgentsTab.tsx` — `lastActiveLabel()` called `Date.now()` during render. Fixed: client-only `now` state that ticks every 30s via useEffect. Server renders placeholder '…', client swaps in real value post-mount. Michael later reverted this too.

Michael's revert on both is noted — the user ran with the hydration mismatches. Working theory: he prefers the correct initial state over the brief mismatch flash.

### Bug 4 — Telegram bot silent timeouts + no screenshot support
`scripts/telegram-kaos.py` had three bugs:
1. 120s `subprocess.run` timeout → any query needing an API call or git operation failed silently with "Timed out"
2. `handle()` only read `message.text`, never `message.photo` or `message.document`
3. Polling loop was not threaded — a 2-minute Claude call froze the bot and piled up pending messages

**Fix:** Full rewrite of `telegram-kaos.py`:
- `CLAUDE_TIMEOUT_SEC = 600` (10 minutes)
- New `download_photo()` calls Telegram `getFile` + downloads to `/tmp/telegram-kaos-photos/`, passes path to Claude with "use your Read tool to open it" instruction
- `handle_threaded()` daemon-threads every message so the poll loop never blocks
- `typing_heartbeat()` thread re-sends `sendChatAction: typing` every 4s (Telegram's indicator expires at 5s) so Michael sees continuous "…typing" during long runs
- Also added missing `import os` — the running process predated an earlier `os.environ.get` edit, which would have crashed on restart

### Bug 5 — WIP deadlock deadlock for po/auditor agents
`pickupStatus === workingStatus` for both: po (`backlog → defined`) and auditor (`released → closed`). The WIP-count query counted unclaimed items in `defined`/`released` as active WIP, so the agent was blocked by its own backlog.

**Fix:** Added `wipExtraFilter: 'started_at=not.is.null'` to both configs in `lib/agent-queue.ts:131` and `:161`. Now WIP counts only claimed items. Also cleared 3 stuck claims (TOD-779 on auditor, TOD-550/542 on PO) that were holding slots indefinitely.

### Bug 6 — Missing `typescript` in node_modules caused 500 on every page
Next.js 14 silently requires `typescript` installed to read tsconfig path mappings. Without it, every `@/*` import fails at build time → 500 on every page. Not obvious because the build command runs fine; the failure is at runtime.

**Fix:** `start.sh` now checks `node_modules/typescript` exists before starting. Runs `npm install typescript --save-dev` if missing. Also added `package.json` `ensure-deps` script with `predev`/`prebuild`/`prestart` hooks as self-healing belt-and-suspenders.

### Bug 7 — Agents kept regenerating the same defective code (rejection loop)
7 issues had accumulated `is_blocked=true` with `rejection_count ≥ 3`. Every re-pickup by Builder produced the identical code because the spawn prompt never mentioned the previous rejection reason, the previous commit hash, or the tester/designer notes. Three-strike loop breaker was doing its job but the loop was pure waste.

**Fix:** `app/api/run-agent/route.ts` now fetches `last_rejection_reason, last_rejected_at, tester_notes, designer_notes, commit_sha` and injects a `<previous-attempt-rejected>` block into the prompt for any issue with `rejection_count > 0`. Tells the agent:
1. Run `git log --all --oneline | grep <task_key>` and `git show <prev_sha>` to see last attempt
2. Fix ONLY the specific defect called out — don't rewrite the whole file
3. If the rejection is a routing/workflow issue (wrong reviewer), DO NOT recode; leave it and PATCH implementation_notes

### Bug 8 — Hardcoded service-role JWTs in 4+ files
Discovered while unblocking TOD-631/767/819: `NotificationBell.tsx`, `lib/circuit-breaker.ts`, `app/api/notifications/route.ts`, `app/api/hub-pause/route.ts` all had `?? 'eyJ...service-role-jwt...'` fallbacks. Client code was shipping the service-role key to the browser.

**Fix:** All four files now throw at import time if env vars missing. No fallback literal. NotificationBell refactored to fetch via `/api/notifications` (no client-side Supabase key at all).

Only `po` or `main` can execute `defined → open`. My earlier retries used `transitioned_by: "builder"` and got 400. Worth noting in any future scripts that try bulk-transitions.

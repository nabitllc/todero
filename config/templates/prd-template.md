## 1. Problem Statement
_What specific user pain does this solve? Who feels it? How often? How bad is it without this?_

## 2. Goal
_One measurable outcome. "Increase X by Y%" or "Enable users to do Z without A friction."_

## 3. Target User
- **Who:** persona + role
- **Context:** when do they need this?
- **Job-to-be-done:** "When [situation], I want to [motivation], so I can [outcome]."

## 4. Success Metrics
- Primary: [the north star metric]
- Secondary: [supporting signals]
- Anti-metric: [what we do NOT want to increase]

## 5. Non-Goals
_Explicitly what this PRD does NOT cover. Prevents scope creep._

## 6. User Stories
- As a [role], I want [action] so that [outcome]
- As a [role], I want [action] so that [outcome]

## 7. Acceptance Criteria
_Explicit pass/fail conditions. Each one should be testable._
- [ ] Criterion 1
- [ ] Criterion 2

## 8. Technical Approach
_High-level architecture. Files to create/modify. Key dependencies. No implementation detail — just enough for Builder to not be surprised._

## 9. Dependencies
_Other features, APIs, or systems required before or during this work._

## 10. Priority Rationale
_Why this priority level? What happens if we skip it or delay it?_

## 11. Revenue Impact
_How does this feature move the needle on MRR, retention, acquisition, or conversion? Estimate if possible._

## 12. Risk Assessment
- Technical risks: [what could go wrong in the code?]
- Product risks: [what if users don't use it?]
- Business risks: [what if it causes churn or legal issues?]

## 13. Rollback Plan
_If this feature causes problems in production, how do we undo it quickly?_

## 14. Analytics & Observability
_What events/metrics to instrument on day 1? What does a healthy rollout look like vs. a failed one?_

## 15. Open Questions
_Unresolved decisions that need answers before or during build._

## 16. Tasks
_Linked task IDs from the board. Populated after PRD is approved._

## PRD Completeness Checklist
A PRD is only APPROVED when all of these are checked:
- [ ] Problem Statement is specific (not vague)
- [ ] Goal has a measurable metric
- [ ] Target User defined with job-to-be-done
- [ ] At least 2 success metrics
- [ ] Non-goals listed
- [ ] At least 3 user stories
- [ ] All acceptance criteria are testable pass/fail
- [ ] Technical approach reviewed by KAOS
- [ ] Revenue impact estimated (even roughly)
- [ ] Risk assessment complete
- [ ] Rollback plan defined
- [ ] Analytics hooks identified
- [ ] No open questions blocking build
- [ ] Tasks created and linked
